# awcms — Performance and Security Standards

A map between the controls that actually run in this repo and the **international
standards that name them**, together with an honest list of gaps.

This document **adds not a single new rule**. The rules already exist — in
[`AGENTS.md`](../../AGENTS.md), in 87 ADRs, and in the 41 gates of the
`bun run check` chain. What has not existed until today is **one place** that
states which standards are followed, which edition, and which controls are
**not** met.

The difference from [`repo-assessment-2026-08-04.md`](repo-assessment-2026-08-04.md):
that assessment is a **snapshot of a single point in time** and must not be
edited afterwards (edit it, and it stops being a snapshot). This document is
**living** — it is updated every time a control lands or is revoked.

> **Content rule.** The status of every row is **verified against the files**,
> not assumed. A row that cannot be proven is written `not yet measured`, not
> `met`. This repo has a long history of guesses written up as findings and then
> copied into decisions (ADR-0058 §1, ADR-0059, ADR-0060) — and the same history
> applies in the opposite direction.

### The edition is a FAMILY-level decision, and this repo owns it

`ahliweb/awcms-astro` states explicitly (ADR-0028 §A in that repo) that it
**matches its OWASP edition to this repo and will not get ahead of it**. The
reason is correct and cuts both ways: two family repos mapping themselves onto
two different editions produce two matrices that cannot be added together, and
whoever reads them will read the numbering difference as a control gap.

The consequence that needs stating here, because nowhere else states it: **the
2021/4.0.3 pin above is inherited, not a decision anyone ever took.** It comes
from the `awcms-security-hardening` skill, written when those were the latest
editions. Newer editions already exist out there. Raising it means re-mapping §3
and §5 **and** telling the neighbouring repo — that is ADR work, not a table
edit. Until that ADR is written this pin holds, and it now **reads as a pin**,
not as currency. See gap **C10**.

## 2. Response headers — and one deliberate difference from `awcms-astro`

What [`buildSecurityHeaders`](../../src/lib/security/security-headers.ts)
actually sends, installed by [`src/middleware.ts`](../../src/middleware.ts) onto
**every** response (JSON API, HTML 404, 42 `.astro` pages):

| Header                         | Value here                                                                                                                                                                      | Value in `awcms-astro`                              | OWASP Secure Headers                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `Content-Security-Policy`      | `default-src 'self'`; `object-src 'none'`; `base-uri 'none'`; `form-action 'self'`; `frame-ancestors 'none'`; `script-src 'self' <theme hash>` (+ Turnstile origin when active) | same, without the theme hash, plus the media origin | Required                                                                                                           |
| `X-Content-Type-Options`       | `nosniff`                                                                                                                                                                       | same                                                | Required                                                                                                           |
| `X-Frame-Options`              | `DENY`                                                                                                                                                                          | same                                                | Required                                                                                                           |
| `Referrer-Policy`              | `strict-origin-when-cross-origin`                                                                                                                                               | same                                                | Required                                                                                                           |
| `Permissions-Policy`           | `geolocation=(), camera=(), microphone=(), payment=()`                                                                                                                          | exactly the same                                    | Required                                                                                                           |
| `Strict-Transport-Security`    | `max-age=31536000; includeSubDomains`, gated on `isProduction`                                                                                                                  | `max-age=31536000` **without** `includeSubDomains`  | Required                                                                                                           |
| `Cross-Origin-Opener-Policy`   | `same-origin`, with no production gate                                                                                                                                          | not sent                                            | Recommended — C2 **CLOSED** here; this inverted difference is now a recorded divergence (ADR-0069, C15 **CLOSED**) |
| `Cross-Origin-Resource-Policy` | `same-origin`, with no production gate                                                                                                                                          | not sent — **explicitly rejected** there            | Recommended — C2 **CLOSED** here; the difference is a recorded divergence (ADR-0069, C15 **CLOSED**)               |

**There is no `'unsafe-inline'` anywhere, and that is not an accident.** The only
inline script in this repo (the admin theme-init) is allowed through a **SHA-256
hash** — one exact byte sequence, not a class. `tests/theme-init-script.test.ts`
goes red when the script body and its hash drift apart; without that gate a hash
mismatch fails **silently** (the script is blocked, with no error, no log).

### The `includeSubDomains` difference is a correct divergence — and it is now recorded

`awcms-astro` deliberately does not send `includeSubDomains` (ADR-0029 in that
repo): it is a **template** running on a domain owned by an organisation that
almost certainly has other services on other subdomains, and that directive
forces all of them HTTPS-only for a year in every visitor's browser. This repo is
**one deployment** whose operator knows its subdomains, so `includeSubDomains` is
correct here.

Both are correct, and since [ADR-0068](../adr/0068-family-standards-posture-editions-and-recorded-divergences.md)
the difference is **recorded**: [`awcms-family-compatibility.yaml`](../../awcms-family-compatibility.yaml)
now carries **three** `intentionalDivergences` entries with reason/owner/
`reviewDate` 2027-02-04 (`hsts-include-subdomains`,
`astro-files-not-type-checked`, the OWASP edition). Gap **C9 CLOSED**.

The difference born from closing C2 — this repo now sends COOP/CORP
`same-origin`, `awcms-astro` does not — **has now been recorded on both sides**
(5 August 2026, gap **C15 CLOSED**). CORP is **explicitly rejected** there
("blocking other sites from embedding images from this site — a decision that
does not belong to a TEMPLATE", ADR-0028 in that repo); COOP is not relevant on
its **template** surface, because that template has no session to fence off; a
derived site that switches on `permukaanAdmin` carries its own session and CSRF
there ([ADR-0070](../adr/0070-peran-keluarga-awcms-astro-memikul-publik-dan-admin-user.md)),
and its COOP decision becomes that site's decision too. The neighbouring repo's
table — which for a while wrote the `awcms` column as "not sent" for both — was
corrected there first in PR #40, and
[ADR-0069](../adr/0069-cross-origin-isolation-divergence-with-awcms-astro.md)
binds that difference to a manifest entry with `reviewDate` 2027-02-04, so it
comes back to the table on the same date as the three ADR-0068 divergences.

### The performance gate: from one surface to four

The `bun run check` chain now carries **34** gates (gate 34 =
`project-state:inventory:check`). Performance is guarded in **four** places, and
the limits of each need to be known:

1. **`db:fk-index:check`** — a chain member, pure, always runs (182
   index-reachable FK columns).
2. **`build:asset-budget:check`** — chained **inside** the `build` script (the
   last chain member), so it runs in CI Quality and in release too:
   `dist/client` ≤ 180,000 bytes total, ≤ 21,000 bytes per file (measured
   baseline 139,048 B, 5 August 2026).
3. **Query budgets** — DB-gated integration tests, now covering the public blog
   path AND the admin dashboard + the admin blog list + the sitemap builder
   (budget = exact actual, with no slack). On a machine without PostgreSQL they
   `skip` with a statement — CI is what runs them.
4. **CWV lab** (`bun run perf:cwv:lab`) — in the E2E job, env-gated

sentence was first written — but field numbers (real visitor p75) are still
absent until the RUM decision is taken.

## 10. What is deliberately NOT adopted

Just as important to write down: a control recommended by a standard and
**rejected with a reason** will not be proposed again six months later as a new
finding.

- **`EDGE_CACHE_MODE` on by default.** A shared cache in front of a multi-tenant
  application is a cross-tenant leak machine when misconfigured. OFF by default
  is the ADR-0042 decision and it is still right.
- **Rate limiting that fails CLOSED.** Rejected in ADR-0066 for a reason that
  still holds: it turns a Redis outage into a total login denial an attacker can
  trigger, while the control that actually binds — the per-principal lockout in
  PostgreSQL ([ADR-0086](../adr/0086-the-lockout-counter-is-global.md))
  — does not depend on Redis at all.
- **Raw per-visit Core Web Vitals rows (ADR-0067 Option C).** It inverts the
  already-written `visitor_analytics` privacy posture (purge = `DELETE` with no
  archive) for a drill-down capability that no recorded need demands.
- **Gating `docs/awcms/` the way `.claude/skills/` is gated.** Its contents are
  deliberately a mixture of history + specification and are not executed as
  instructions; [ADR-0062](../adr/0062-skills-are-gated-against-the-code-they-describe.md) §3
  already states that boundary. **This** document is the stated exception:
  it is current-state, so it must be updated when a control changes.
- **Raising test coverage for the percentage.** 293 test files with a consistent
  mutation-proven pattern are worth more than a coverage number — what is
  missing is not quantity but **class** (gaps C4, C5).

## 12. How to use this document

1. **Before an audit/go-live** — read §9. An `OPEN` gap that does not show up in
   `bun run security:readiness` is exactly the one nobody will remind you about.
2. **When adding a control** — add its row in §3–§8 **together with its file
   evidence**, and move its gap to `CLOSED` with a checker that actually landed.
   A row without a checker is a claim, not a control.
3. **When asked about compliance** — §3 through §7 are the answer you can send.
   §9 is the part that makes it trustworthy.
4. **When raising a standard's edition** — that is a family-level ADR, and the
   neighbouring repo follows, it does not lead.
