docs(api): the public contract now declares `429 RATE_LIMITED` and the `Idempotency-Key` header exactly where a handler applies them (Issue #1385, findings F-08/F-09 of the consumer contract-parity audit). New shared components: `components.headers.RetryAfter`, `components.responses.RateLimited` (429 with `Retry-After`) and `RateLimitedNoRetryAfter` (for the handlers that answer 429 without the header), and `components.parameters.IdempotencyKeyOptional` (ADR-0129 §2). Six operations that answer 429 but did not declare it (`POST /setup/initialize`, `POST /analytics/collect`, `POST /comments/{id}/report`, both session-handoff operations, `GET /auth/sso/{providerKey}/callback`) now do, 47 already-declared 429s gain the `Retry-After` header their handler sends, `POST /blog/institutions/{id}/purge` declares the required `Idempotency-Key` it enforces, and `PATCH /website-engagement/sources/{id}` declares it optional (it is required only when `challengeMode` is set to `none`). The bundler now carries root `components.headers`. A new per-handler test (`tests/openapi-rate-limit-and-idempotency-declared.test.ts`) follows each route handler through the helpers it calls and fails when a rate-limited operation lacks 429, a 429 disagrees with the handler about `Retry-After`, or an operation reads or declares the idempotency header without the other. No handler behaviour changes.
