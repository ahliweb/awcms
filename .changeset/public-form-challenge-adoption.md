feat(security): the remaining pre-session forms and widgets move onto the public-form challenge seam (Issue #1353, module contract 4.9.0). The login, register, forgot, reset and accept-invitation pages render the widget the ENABLED provider declared (`ModulePublicFormChallengeProvider.widget`; Turnstile today) through `PublicFormChallengeWidget.astro` instead of hard-coding Turnstile per page, send the solved fields with `readChallengeFields`, and no longer send the legacy `turnstileToken` (the server still accepts it: it is a published, OpenAPI-documented field); `/accept-invitation` now carries the widget (it could not complete when Turnstile was on). The middleware opens the declared `cspOrigins` in `script-src`/`frame-src` for the enabled provider only (malformed origins are dropped). Modules declare the public forms they own and their routes (`ModuleDescriptor.publicFormChallengeForms`), so the integration harness keeps no shared route-to-form table (`PUBLIC_FORM_ROUTE_FORMS` removed) and `extension-points:check` fails an undeclared or stale route. `POST /api/v1/newsletter/subscribe` and `POST /api/v1/comments` call the seam once each (off by default; with Turnstile on, the single `TURNSTILE_EXPECTED_HOSTNAME` binding means tenant sites on other hosts are refused, see `docs/awcms/public-form-challenge.md` section 6). No migration; default behaviour unchanged. OpenAPI now documents the optional `challengeId`/`challengeAnswer`/`challengeToken` and legacy `turnstileToken` request fields on both routes (a new `SubmitTopLevelCommentRequest` for the comment POST, so replies and edits do not claim them) and the `TURNSTILE_REQUIRED`/`TURNSTILE_INVALID` 400 that only appears while a provider is on; a gate test fails if a declared challenge route's request schema omits them. The route gate also treats any reference to `enforcePublicFormCaptcha` (aliased import, namespace member) as a call.
