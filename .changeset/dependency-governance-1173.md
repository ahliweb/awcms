chore(deps): dependency freshness and upgrade governance (#1173). Governance only — no dependency version changes in this PR. Adds `bun run deps:freshness` (`scripts/dependency-freshness.ts`), a READ-ONLY report of `bun outdated` drift on direct dependencies, `bun audit` (evaluated with the same `evaluateAudit` and exception list as `deps:audit:check`), the pinned Bun version vs npm latest, and the pinned base images (`Dockerfile.production`, `deploy/cron/awcms.crontab`) vs the newest same-shape Docker Hub tag with a check of the digest recorded in the Dockerfile. A check that cannot run (registry unreachable, output not parseable) is reported as `UNKNOWN`, never as "no drift"; `--strict` exits 1 on any UNKNOWN section, an unhandled high/critical advisory, an expired or stale held-back entry, or a mismatched recorded digest. New `.github/workflows/dependency-freshness.yml` runs it weekly (Monday 02:00 UTC) and on dispatch with `contents: read` only, publishing the report to the run summary and the JSON manifest as an artifact; it opens no PR and edits no file. New held-back register `scripts/dependency-held-back.ts` (package, held version, reason, owner, review date) whose entries expire by date and go stale when no longer behind, pinned by `tests/dependency-held-back.test.ts`; first entry is the deliberate Bun 1.3.0 `engines`/`minimum-supported` floor. New `docs/awcms/dependency-governance.md` (+ `.id.md`): cadence, severity handling, the atomic one-upgrade-per-PR rule, the gates each upgrade must pass, the Bun pin-bump playbook, rollback, and how the report and register are used. Not delivered here and still open on #1173: license/SBOM aggregation, provider API changelog tracking, and automatic issue creation for validated gaps.
