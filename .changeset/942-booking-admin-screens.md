feat(booking): admin screens for resources and units, pools, offerings, schedules and closures, blocked nights, reservations (list, hold and expiry, detail with history and transitions) and the policy (#942, epic item 16, generic half). Six pages under `/admin/booking/` over the #1030 admin APIs and the existing reservation, block and schedule routes; no migration and no API change. Each is a `navigation` entry of `booking` whose `requiredPermission` is seeded (`sql/181`) and enforced by the route it drives, so the module moves from `experimental` to `active` (ADR-0021 criterion 1). Every mutation carries a fresh `Idempotency-Key` through one shared sender; refusals are translated sentences keyed by the API's error code (en and id catalogues, 218 entries); delete, cancel, no-show, release and deactivate use the native confirm dialog; every action has a keyboard path (Playwright flow, axe in both themes and the 360 px sweep cover the screens). The reservation detail is a view of the list page (`?id=`), never showing the customer reference or note. Creating, rescheduling and overriding a reservation, the availability search, notes and reports are not on a screen (the admin-screen coverage ledger keeps those seven permissions). `APP_BUDGET_BYTES` rises by the measured 11,259 B of the new scripts.
