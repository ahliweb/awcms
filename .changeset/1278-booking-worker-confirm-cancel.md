fix(booking): `BookingPort.confirm` and `.cancel` work as `awcms_worker`, the defect tests tolerate a downstream foreign key, and `booking/module.ts` no longer closes an import cycle (Issue #1278, ahliweb/awcms-one#420 items 4, 6 and 7).

**Worker-callable confirm and cancel** (migration `sql/388`). A consumer that confirms or cancels from `domain-events:dispatch` runs as `awcms_worker`, which deliberately holds no privilege on the booking tables, so both verbs were refused under a least-privilege `WORKER_DATABASE_URL`. When the connection's `current_user` is `awcms_worker` the port now calls `awcms_booking_worker_transition(tenant, reservation, action, actor, correlation, reason)`, a narrow SECURITY DEFINER function in the pattern of the hold-expiry sweep (`sql/200`, `sql/209`): a dedicated NOLOGIN memberless owner (`awcms_booking_transition`, column-scoped privileges, pinned in `security:readiness`), `search_path` pinned, the tenant argument must equal the session tenant context (42501 otherwise), EXECUTE for `awcms_worker` alone, and `action` is `confirm` or `cancel` and nothing else. Same transitions, same refusals (`RESERVATION_NOT_FOUND`, `INVALID_STATE`, `HOLD_EXPIRED`), same layer-2 replay, same history row, and the audit row and domain event are written by the same functions. Nothing changes for any other role or any other verb. **Open decision:** the worker path stores no Idempotency-Key record (the worker has no INSERT on the store); it still honours a stored one and is retry-safe through the state check. Check-in, completion and no-show have no worker path.

**Defect tests** (`booking-concurrency` T7, `booking-stay` T13): the `TRUNCATE` is now `CASCADE`, and both tests create an empty table with a foreign key into the reservations first, so a downstream dependent can no longer refuse it.

**Import cycle**: `createComposedBookingPort()` (same signature) loads `booking-port-adapter` at the first call instead of at import, which removes the path `booking/module.ts` to `consumer-registry` to `src/modules/index.ts` that made `booking-admin-api`, `booking-block-api` and `booking-reservation-api` fail with a `bookingModule` temporal-dead-zone error when run alone.
