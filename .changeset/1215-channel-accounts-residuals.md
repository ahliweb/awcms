security(channel-accounts): close the agent-actionable residuals of Issue #1215. The abandoned-OAuth-authorisation sweep now also runs hourly as `bun run channel-accounts:oauth-state:sweep` (an `awcms_app` job, bounded per tenant, a failing tenant never stops the others, no key ring needed), instead of only when the same tenant starts another flow. `GET /api/v1/channel-accounts/connections` and `GET .../accounts/{id}/assignments` are keyset-paged (`limit`, `cursor`, response `{ items, nextCursor }`, a breaking response-shape change on both: the bare array is gone; the admin screen shows the first 100 connections with a notice). Having started a connection is authority over a tenant-wide connection only, not over a scoped one whose scope the creator no longer holds. `APP_URL` must now be `https:` unless `APP_ENV=development` for the OAuth redirect URI (decided fail-closed, also enforced by `config:validate` when `CHANNEL_ACCOUNTS_ENABLED=true`). New platform-scoped operator screen `/admin/channel-account-claims` for the ADR-0170 claim release (platform permission, MFA step-up, typed confirmation, `Idempotency-Key`). The channel-account block of `.env.example` is back in its own section. The cross-tenant existence oracle of `registration`-basis ids is documented as not removable; hierarchy containment remains an owner question.
