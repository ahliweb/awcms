security(identity_access): `awcms_setup` can no longer read credential columns (#1082, found by the security review of #1078). `sql/022` gave the one-time setup role a table-level `SELECT` on `awcms_identities`, which included `password_hash`; an operator can activate that role for LOGIN, and RLS trusts a session setting the caller picks. `sql/310` revokes it and re-grants only what `POST /api/v1/setup/initialize` (`bootstrapPlatformTenant`, the role's only flow) reads: `SELECT (id, principal_id)` and `UPDATE (principal_id)` on `awcms_identities`. It also fixes a pre-existing break found while proving the wizard works: under `SETUP_DATABASE_URL` the wizard failed with `permission denied for table awcms_principals` since ADR-0086. The principal find-or-create is now the SECURITY DEFINER function `awcms_ensure_principal_id(text)` (owner `awcms_principal_ensure`, NOLOGIN and memberless, returns only the id, never `password_hash`), so `awcms_setup` holds no direct privilege on `awcms_principals`; `principal-store.ts` uses it for every caller. Because `UPDATE (principal_id)` would otherwise let the setup role repoint a linked identity (account takeover), the link is one-way: a BEFORE UPDATE trigger rejects changing a non-NULL `principal_id` for every role (no code path repoints; every writer already says `principal_id IS NULL`) and a RESTRICTIVE policy limits `awcms_setup` to `principal_id IS NULL` rows with an explicit `WITH CHECK (principal_id IS NOT NULL)`. `security:readiness` check "Worker and setup roles cannot read credential columns" now covers `awcms_setup` with an explicitly empty exception list (the worker exceptions do not extend to it), `SETUP_COLUMN_GRANTS` pins the setup column grants, and the grants check now sweeps EVERY awcms_ table for column-level privileges held by `awcms_setup` and `awcms_worker` (previously only pinned tables were inspected, so a stray column grant elsewhere passed); it found one unpinned legitimate grant, `awcms_worker` UPDATE on `awcms_booking_reminder_intents` (sql/284), now pinned. It also fails if the link-once trigger or policy is missing. Encrypting `awcms_push_subscriptions.auth_secret` at rest is deliberately not part of this change (needs a runtime backfill).
