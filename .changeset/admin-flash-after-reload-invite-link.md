feat(admin): a shared "flash after reload" primitive, used by `/admin/invitations`, and an "Invite user" link on `/admin/users` (Issue #1328). Creating, resending or revoking an invitation reloaded the page and said nothing, so a success looked like a click that never registered. `flashAndReload(key)` / `showFlash(id)` in `src/lib/ui/admin-form-client.ts` carry a short catalog KEY (`^[a-z0-9-]{1,40}$`) across the reload in `sessionStorage`, never message text or response data; the sentence shown is the page's own server-rendered, already-translated text for that key (`data-flash-<key>` on the notice element), the key is removed as soon as it is read, and blocked storage still reloads without breaking the page. Screens that handle secrets keep their stateless `?notice=` allow-list and do not use it. `/admin/users` shows the link only to a caller holding both `identity_access.invitations.create` and `.read` (the destination renders nothing without `read`). en/id strings, README en/id, tests for the client primitive and both page contracts. No endpoint, permission or migration change. The app client asset budget is raised by 500 B (365,600 to 366,100) with the measurement recorded beside it.
