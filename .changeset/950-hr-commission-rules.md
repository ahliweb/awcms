feat(hr_commission): versioned commission rules, the phase 2 rule foundation of the hr_* family (#950, ADR-0132). New module `hr_commission` (`experimental`, flag off, depends only on tenant_admin and hr_workforce): jurisdiction-neutral, tenant-authored commission rules (a percent of a base amount or a fixed amount per unit, one currency, an explicit rounding mode and scale, an optional floor and ceiling) with draft, publish and retire. A draft is editable; a published version is immutable and may only become retired, a retired one never changes, no row is ever deleted, and no two published windows of one rule overlap (including under concurrent publishes) — all enforced by database triggers. Publish and retire are high-risk, separately grantable, idempotency-keyed and audited without any rate or amount (the publish audit row carries a content digest of the published terms); publish and edit name the content digest they were based on (409 when the terms moved) and the draft's creator or last editor cannot publish it (maker / checker); every money column refuses NaN, a row is born a draft, and a result that would not fit numeric(18, 6) is refused. Evaluation is a pure function over `bigint` decimal strings (no float, no expression language, no tiers) with table tests; money crosses the API as decimal strings and a JSON number is a 400. A rule references no person or employment. Migrations `sql/182`-`sql/183` (schema, permissions); existing tenants need `identity-access:permissions:backfill`. Registered with data_lifecycle (retained, never purged) and subject-data (actor stamps only); no admin screen yet. The accrual ledger, its lifecycle and the source-event port are later phases.
