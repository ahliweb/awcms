feat(data_lifecycle): delegated retention snapshots now report real backlog counts for the 25 inventory, procurement, HR-workforce and booking tables the worker may not read (#1042, `sql/303`, follow-up to #1040). One count-only `SECURITY DEFINER` function per owning module (`awcms_{inventory,procurement,hr_workforce,booking}_lifecycle_eligible_count(p_table, p_tenant_id, p_cutoff)`) returns a single integer, never a row; `search_path` is pinned to `public, pg_temp`, `EXECUTE` is granted to `awcms_worker` only, each function is owned by a dedicated NOLOGIN role holding column-level `SELECT (tenant_id, cursor column)` on its module's tables, RLS is untouched (tenant scoping relies on the caller's own `app.current_tenant_id` under FORCE RLS with a NOBYPASSRLS owner, plus `p_tenant_id`; it adds no capability beyond the worker's existing per-tenant iteration and is not a boundary against the worker) and an unknown table name raises `22023`. `planLifecycleDryRun` calls it for tables listed in `DELEGATED_COUNT_FUNCTIONS`; held, purgeable and blocked are still derived in TypeScript from the legal-hold records. `KNOWN_UNREADABLE_DELEGATED_TABLES` is now empty, and `data-lifecycle:worker-grants:check` verifies from `sql/` that every mapped function is granted to the worker and has a branch for its table. No row-level `SELECT` was granted to the worker, and no payroll relation is reachable.
