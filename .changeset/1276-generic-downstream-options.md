fix(data-lifecycle, payroll-boundary, csv): three generic options carried downstream (Issue #1276). (1) The generic archive/purge engine and the dry-run planner cast the cutoff, resume and archived-through parameters of every cursor comparison (`$N::timestamptz`), so a descriptor whose cursor column is `date` runs instead of failing with `22007`; a no-op for a `timestamptz` cursor. `runGenericArchivePass` and `runGenericPurgePass` are now exported for tests. (2) `NON_PAYROLL_TABLE_NAME_EXCEPTIONS` in `payroll-data-boundary.ts`: a registered, reasoned list of exact non-payroll table names (plus `<table>_...` objects whose remainder is not itself a payroll name), consulted by `isPayrollTable` before the patterns; empty today, validated at load (reason required, never a required payroll table, must be a real pattern hit). (3) `csvCellForWrite(value, { numericText: true })` writes a string that is only an optionally signed decimal as is; everything else is neutralised as before. No behaviour change for existing callers; no migration. Audit follow-up: (1) the cutoff comparison is no longer a bare `::timestamptz` cast (which compared a `date` column through the session TimeZone and made the cutoff day eligible); a descriptor may declare `cursorColumnType: "date"`, compared against the UTC calendar date of the cutoff, and a date cursor is purge-only (the registry gate and the engine refuse it with `archive.archivable: true`, since rows sharing a day cannot be resumed and would be purged without an archive); the header claim that the engine never purges without an archive is corrected. (2) A `NON_PAYROLL_TABLE_NAME_EXCEPTIONS` entry now frees only the table itself and its catalog objects (`_pkey`, `_<cols>_idx|key|fkey|check|seq|trg`, no other table's stem), and an entry that is, or is a prefix of, a known payroll table is refused at load.
