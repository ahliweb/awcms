security(social_publishing): the social dispatcher re-checks the SOURCE of every job immediately before the provider call (Issue #1145, residual L8 of ADR-0157, a condition before the first connector may publish). The content snapshot still decides what is sent; in the pre-send transaction, before any credential is decrypted, the dispatcher now asks `blog_content` whether the source article is still published publicly (new port `ArticlePublicationStatusPort`, capability `article_publication_status` 1.0.0) and `media_library` whether the media object is still available and cleared (new `MediaPublicationRecheckPort`, capability `media_library` 1.0.0 to 1.1.0, additive). An article unpublished, archived, made private, deleted or past its `unpublish_at` after enqueue fails the job `SOURCE_RETRACTED`; a media object missing, soft-deleted (taken down) or no longer `verified`/`attached` fails it `MEDIA_UNAVAILABLE`; a rights adjudication no longer `verified` or an unknown copyright status fails it `MEDIA_RIGHTS_REVOKED` (`fair_use` stays accepted, as at enqueue). These are terminal: the provider is not called, the breaker is not charged, the dispatcher never retries them, and the audit row carries ids and the code only. A re-check that cannot be answered (a database error) is never read as "may send": the job waits as `SOURCE_CHECK_UNAVAILABLE` within its retry budget. Migration `sql/386` answers both questions through two SECURITY DEFINER functions (`awcms_social_source_article_state`, `awcms_social_source_media_state`) owned by a new NOLOGIN, memberless role `awcms_social_source_check` with column-only reads, `search_path = public, pg_temp`, and the tenant argument bound to the transaction tenant; EXECUTE is granted to `awcms_social_dispatch` only, whose only new grant is `source_kind`, `source_id` and `media_object_id` of its own publications (no read of the posts or the media registry). `security:readiness` pins both functions exactly (body, owner, `search_path`, volatility, EXECUTE list) and both roles' column matrices, and probes every verdict in a rolled-back transaction. `DispatchSocialPublishOptions.sources` is now required. No API or event contract changes.
