Add the `crm_leads` module: the reusable lead/prospect pipeline admitted by ADR-0153 (Issue #1166), a pre-customer context that never owns the customer, the identity or the consent. Tenant-defined pipelines with a versioned, immutable stage catalog (closed stage categories, edges with closed declarative guards, explicit audited stage migration when a revision removes an occupied stage); lead intake idempotent on the source key as well as the `Idempotency-Key`, with an immutable first source touch; contact points stored as ciphertext plus a per-tenant keyed hash plus a masked form; append-only transition history decided under row locks with optimistic concurrency; identity candidates by exact hash inside one tenant; human-verified, undoable merges; conversions recorded from the customer authority (an opaque external reference) or a flagged manual path and reversed by event; soft delete, restore and anonymising erasure that keeps funnel counts. Outbox events `awcms.crm_leads.lead.*` carry opaque ids only; a `CrmLeadPort` (capability `crm_lead` 1.0.0) serves a downstream authority. Migrations 342-344; new env `CRM_LEADS_ENABLED` (off by default) and `CRM_LEADS_KEYS`. The module is `experimental` with no admin screen yet and is also switched off per tenant until a holder of `crm_leads.pipelines.configure` enables it. New permissions need the owner or an administrator to grant them to a role (existing tenants: `bun run identity-access:permissions:backfill`).
