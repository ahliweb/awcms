Close the new findings of the independent audit of #1218 before `CHANNEL_ACCOUNTS_ENABLED` is ever turned on (Issue #1215; the module is off by default and has no consumer yet). Medium: the scope of an account must now be contained in the scope of the connection it binds, with no administrator exception (a tenant-wide account may bind only a tenant-wide connection; a scoped connection admits only an account of exactly that scope), so a tenant administrator can no longer carry a scope-B connection's token out of scope B; the `account.create` audit row records the internal `connectionId`. LOW-1 (ADR-0080): the administrator bypass requires `assignments.assign` through a tenant-wide grant, so a grant confined to one scope cannot act as the administrator of every scope. LOW-2: the connection-id shape is validated before the connection is looked up, so no registration answer depends on whether the id exists. LOW-3: binding to a connection with no account yet needs the revoke authority (creator or break-glass), and break-glass asks the tenant-level question first so an administrator's connection list writes no per-scope decision rows. L4: integration tests for the `business_scope_*` immutability triggers. L7: `APP_URL` is required when the module is enabled (config validation and the runtime both fail closed; no built-in default callback host). N7: the key-ring sharing check now also covers the WhatsApp recipient-hash ring. OpenAPI, the module README and ADR-0148 (EN and ID) record the binding rule. Not changed: the assignment model (M-c), external-id squatting, N2, N3 and any migration.
