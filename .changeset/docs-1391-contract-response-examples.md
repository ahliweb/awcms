docs(api): response examples for three representative operations, validated by the contract gate (Issue #1391, ADR-0167). `GET /api/v1/blog/posts` carries `summary`, `stable_order` and `view=full` examples plus 400/401/403; `POST /api/v1/newsletter/subscribe` carries ONE neutral 200 (it cannot tell a new address from a known one), a 400 and a 429; `PUT /api/v1/booking/policy` carries 200, two 400s, 401, 403, 409 and 422, all with synthetic data (`example.test`, reserved domains only). `bun run api:contract:lint` now also validates every `example`/`examples` of the bundle against its schema with `ajv` (media types, parameters, schema level; uuid/date-time/email/uri enforced; a non-reserved e-mail domain fails). Contract changes: `required` completed where the handler always returns the field (`NewsletterNeutralResult`, `BookingPolicy.effective`, the booking PUT envelope and `replayed`, `BlogPostSummary.publishedAt`); the list `view=full` element is a new `BlogPostFeedItem` (the `BlogPost` with the feed fields guaranteed) and `BlogPostSummary` is now `additionalProperties: false`, which also repairs the list `oneOf` (a full post used to match both branches). The astro consumer-contract fixture is regenerated on purpose, because the frozen `$ref`/`oneOf` structure of two consumed paths (`GET /api/v1/blog/posts`, `POST /api/v1/newsletter/subscribe`) has to change to carry examples; every field `awcms-astro` reads is unchanged (`BlogPostFeedItem` is a superset of `BlogPost`). No runtime change.
