security(push_delivery): encrypt `awcms_push_subscriptions.auth_secret` at rest, backfill-safe (#1089, follow-up to #1082). `sql/314` adds `auth_secret_ciphertext` (AES-256-GCM through the ADR-0137 helper, own key ring `PUSH_AUTH_SECRET_ENCRYPTION_KEYS`, AAD = tenant + `endpoint_hash` because registration is an upsert whose surviving row `id` is unknown beforehand), replaces the transport CHECK with "exactly one of plaintext/ciphertext", and narrows `awcms_worker` `UPDATE` on the table to the columns jobs write (pinned in `WORKER_COLUMN_GRANTS`, so the worker can no longer rewrite `endpoint`). Registration writes ciphertext only and fails closed (`503 PUSH_MISCONFIGURED`, capability `webPush.enabled=false`) without the key ring, with no plaintext fallback; re-registering a legacy row migrates it. The dispatcher decrypts ciphertext (never falling back to plaintext when it fails) and reads the legacy plaintext only for a row with no ciphertext; a missing ring or rotated-away key is a retryable failure, a failed authentication is not. New idempotent, resumable, batched keyset job `bun run push:auth-secret:backfill` (worker role) encrypts the remaining rows and NULLs the plaintext. `security:readiness` gains a warning check that reports how many plaintext rows remain; the `auth_secret` worker exception stays (documented as transitional) and `auth_secret_ciphertext` is added as a ciphertext exception. The plaintext column is NOT dropped here: a later migration drops it and the exception once every deployment reports zero. Rollout order and trade-offs: `docs/awcms/push-notifications.md`. New env `PUSH_AUTH_SECRET_ENCRYPTION_KEYS` (required for `PUSH_PROVIDER=web_push`); set it before deploying.
