feat(api): contract-derived fixtures pack with a freshness gate (Issue #1392, ADR-0167). `bun run api:fixtures:generate` writes `fixtures/api-contract/contract-fixtures.json` from the bundled OpenAPI contract: for every operation a request-body example and one example per declared JSON response (the examples of #1391 are used as declared; everything else is synthesised from the schema: `$ref`, `allOf`, `oneOf`/`anyOf`, `const`/`enum`/`format`/bounds, cycles cut at the first repeated `$ref`), error responses shared through `components.responses` are emitted once. Every fixture is validated with the same `ajv` as `api:contract:lint` (formats enforced) and checked for reserved e-mail domains; what cannot be built is listed under `skipped` with its reason (today 4: three `text/event-stream` and one `text/plain` response), never dropped silently. The output is deterministic (two runs are byte-identical) and `bun run api:fixtures:check`, now in `bun run check` right after `api:contract:lint`, fails when the contract changed and the pack was not regenerated. No new dependency (`ajv` and `yaml` only); no migration; no runtime change. Publishing the pack as a pinned artifact (#1394) and handler response conformance (#1393) are separate issues.
