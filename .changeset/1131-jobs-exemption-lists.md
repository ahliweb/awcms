Harden the exemption lists behind per-job secret scoping (Issue #1131, part L4). `UNTRACEABLE_IMPORT_SITES` is now keyed by file AND the exact `import(...)` expression, counted per occurrence, so a second computed import in `scripts/table-write-ownership-check.ts` (or a changed one) fails `tests/jobs-env-scoped-reach.test.ts` instead of being accepted; the tracer now reads a dynamic import's whole argument (nested calls and template literals) rather than stopping at the first `)`. `REACHES_WITHOUT_READING` no longer skips the reader file: every read of the variable and every reference to a listed reader function must sit inside another listed function, so a new helper in `telegram-config.ts` that calls a ring resolver internally fails the test. That check immediately found a real gap, `resolveTelegramHashRing` reads the encryption ring and is now listed as a reader of `TELEGRAM_CHAT_ENCRYPTION_KEYS`. `ops/run-job.sh` refuses the `OPERATOR_ONLY_TARGETS` (`bench:booking`, `config:validate`, `security:readiness`, `subject-data:coverage:check`, `telegram:webhook:register`) by name before it calls docker, from a block `bun run jobs:env-allowlist:generate` writes into the script (`jobs:env-allowlist:check` fails when it is stale), and refuses any target that is not a plain package-script name so `bun run <path>` cannot run a file around the refusal.

**Operator action:** replace `ops/run-job.sh` on the host with the one from this release. The env files are unchanged. Run `config:validate`, `security:readiness` and `telegram:webhook:register` with the deployment's full environment, not through `run-job.sh`.
