feat(observability): delivery-queue health for provider outages, and a runbook for uncertain outcomes (Issue #1412). The audit of the existing telemetry found three gaps and one defect, and adds only what was proven absent, through the existing metrics port (no new metrics path, no shared gateway, no external service). New low-cardinality series, all with a single code-defined `queue` label: gauges `queue_pending_count`, `queue_oldest_due_age_seconds` and `queue_expired_lease_count` (email, whatsapp, telegram, push, object sync; one aggregate per tenant and queue over non-terminal rows on the existing dispatch index, run inside the dispatcher that already iterates tenants), and counter `queue_uncertain_outcome_total` (email, social publishing, telegram engagement). Each of the five dispatchers also prints a fixed job-log line `<job> queue — pending=N oldestDueAgeSeconds=N expiredLeases=N`, because no metrics adapter is registered by default and a cron dispatcher exits within seconds. A probe that fails is logged (sanitized, no tenant id) and records nothing, never a false zero. The defect: `domain_event_delivery_backlog` and `domain_event_delivery_oldest_pending_seconds` were set once per tenant, so the last tenant of the loop overwrote every other tenant's lag; they are now aggregated across tenants (counts add, oldest age is the maximum) and recorded once per run. New runbook `docs/awcms/provider-outage-runbook.md` (+ `.id.md`): evidence table of what exists versus what was added versus what is absent, per-process breaker visibility (not a global provider oracle), detect, classify sent/unknown/failed, hold, reconcile, authorized replay, rollback and incident steps, fault-test drills, cost budget and redaction, and SLI/SLO as proposals that require a measured baseline. Provider 429/5xx counting is deferred to the outcome classification of #1410 and `circuit-breaker.ts` is untouched. Verified against a real PostgreSQL as the `awcms_worker` role (`tests/integration/queue-health.integration.test.ts`) and a fake-SQL unit test (`tests/queue-health-metrics.test.ts`).
